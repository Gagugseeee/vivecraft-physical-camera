# Онлайн-сборка VR Physical Camera без установки Java и Gradle

Здесь собрана ПОЛНАЯ версия проекта v0.2.0, плюс `.github/workflows/build.yml`, чтобы собирать мод на GitHub Actions.

## Что делать

1. Создай бесплатный аккаунт на https://github.com/ (если его ещё нет).
2. Открой https://github.com/new и создай репозиторий `vivecraft-physical-camera`, желательно Public (в публичных репозиториях GitHub-hosted Actions без поминутной платы). Выбери главную ветку `main` (обычно создаётся автоматически).
3. Распакуй ZIP на диск D:. Это очень маленький архив исходников — Java и Gradle на ПК не нужны.
4. Открой созданный репозиторий. Нажми `Add file` → `Upload files`. **Перетащи СОДЕРЖИМОЕ папки `vivecraft-physical-camera`**, не сам ZIP. Обязательно сохрани папки `src/main/...` и скрытую `.github/workflows/build.yml`. Проверь, что `build.gradle` расположен **в корне** репозитория, а не во вложенной папке.
5. Нажми `Commit changes` / `Propose changes`, чтобы сохранить файлы.
6. Перейди на вкладку `Actions` → `Build VR Physical Camera JAR` → `Run workflow` (или открой автоматически запущенный процесс от загрузки файлов). При первом запуске GitHub может попросить разрешить Actions.
7. Если сборка зелёная, открой её → блок `Artifacts` → `VR-Physical-Camera-JAR` → скачай ZIP. Распакуй его: внутри будет `.jar`.
8. Помести `.jar` в `.minecraft/mods` вместе с совместимыми Fabric API, Vivecraft, Flashback.

## Если красный крестик / FAILURE

Наш исходный проект ранее НЕ компилировался в реальной среде, поэтому могут проявиться ошибки зависимостей или несовместимых API. В этом случае: Actions → красная сборка → build → Compile mod → скопируй раздел FAILURE и строки error, пришли их в чат. Это не означает, что на ПК не хватает места.

## Как устроена онлайн-сборка

`.github/workflows/build.yml` скачивает Java 25 и Gradle 9.6.0 **на временный сервер GitHub**, запускает `gradle build` и выкладывает JAR как Artifact. Ни Java, ни Gradle на твой компьютер не устанавливаются. Тебе понадобится только место для небольшого архива и итогового JAR.

Важно: если браузер не переносит скрытую папку `.github`, проверь, что workflow действительно появился в репозитории. При необходимости создай её вручную через `Add file` → `Create new file` с путём `.github/workflows/build.yml` и скопируй текст из распакованного файла.
